ハードウェア、OS、NetHack のインターフェースによっては、使えないキー入力があります。

たとえば ^S と ^Q は XON/XOFF フロー制御によく使われます。^S で出力が止まり、続く ^Q で再開します。その場合、どちらの文字も NetHack がコマンド入力を待っているときに届きません。そのためコマンドには使われていませんが、NetHack まで届かない場合、'whatdoes' がそう教えられるとは限りません。

^M、<return>、<enter> は、NetHack に渡される前に ^J、<linefeed>、「改行」に変換されることがよくあります。そのためコマンドには使われていません。^M を入力して ^J の説明が出ると、'whatdoes' が違う文字を報告しているように見えますが、正しく動作しています。

NUL 文字は、キーボードによって ^<space> や ^@ で入力でき、まったく入力できないこともあります。NUL はコマンドには使われず、'whatdoes' に届く前に ESC に変換されます。^M と違い、この変換は NetHack の内部で行われます。ただし ^M と同じく、NUL を入力して ESC の説明が出るのは想定どおりの動作です。

ESC は ^[ と同じ文字で、これも奇妙な動作の原因になります。カーソル矢印キーなど多くのファンクションキーは、ESC + [ + その他からなる「エスケープシーケンス」を送ることがあります。すると NetHack はどのコマンドが意図されたのか分からなくなります。ESC が処理された後、続く文字はプレイヤーが入力したもののように扱われるからです。（ファンクションキーを押して着ている防具のメニューが出たら、それはエスケープシーケンスが送られたためです。ESC が保留中のキー操作を取り消し、'[' が着ている防具を表示するコマンドとして扱われ、「その他」の部分はメニューを閉じるときに無効な選択として黙って捨てられたのでしょう）

NetHack の 'altmeta' オプションが有効なとき、つまり <alt> や <option> キーを Shift のように使って別の文字を入力すると ESC とその文字が送られ、NetHack がそれをメタ文字として扱うときは、ESC はさらに紛らわしくなります。ESC + 何かの2文字を扱うには、NetHack は ESC を受け取ってから次の文字を待たないと何をすべきか決められません。そのため ESC を手で入力したときは、もう一度入力しないと NetHack は待ったままになります。（その場合は M-ESC ではなく、ESC を入力したものとして扱われます）

システムによっては、^\ を入力すると実行中のプロセスに QUIT シグナルが送られ、プロセスが終了してコアダンプが保存されることがあります。この文字は NetHack のコマンドには使われていないので、入力しないでください。

最後に：^x と書かれた文字は、<control> や <ctrl> キーを Shift のように押しながら 'x' を入力するという意味です。コントロール文字はすべて暗黙に大文字として扱われますが、入力時に Shift キーを押す必要はありません。メタ文字は逆で、大文字と小文字を区別します。大文字のメタ文字を入力するには、<meta> や <alt> に加えて Shift も押してください。
