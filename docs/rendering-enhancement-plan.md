# レンダリング強化 方式整理（壁形状・ライティング・探索境界）

2026-11-09 時点の設計メモ。高解像度タイル制作（[hires-tiles.md](hires-tiles.md)）と並行して進める、
描画側の強化案と実現方式をまとめる。

**進捗**: P0（共通シェーダーの分離）と P1（探索境界のフェード）を実装済み。詳細は 5 章の「実装済み」を参照。

## 0. 現状の把握

| 項目 | 現在の実装 | 場所 |
| --- | --- | --- |
| 地形マテリアル | `MeshBasicMaterial`（非ライティング）。`patchMaterialForVignette` で全地形・ビルボードのシェーダーに共通処理を差し込む | [lighting.ts](../src/game/engine/rendering/lighting.ts) |
| 明暗 | プレイヤー中心の距離ビネット（半径 20 タイル、最大 82% 暗く）。部屋の明暗・光源は考慮しない | 同上 `vignetteUniforms` |
| 面の陰影 | `FACE_SHADE_GLSL`: スクリーン空間微分から法線を出し、北西のキーライトで側面を暗く・足元を暗く | 同上 |
| 壁ジオメトリ | 通常は直方体。FPS モードのみ角を 45° 面取り（4bit マスク: NW/NE/SE/SW）。面取り判定は「その角の直交 2 隣がどちらも通行可能か」 | [wall-geometry.ts](../src/game/engine/rendering/wall-geometry.ts) `computeFpsWallChamferMask` |
| 面取りで空いた床 | 床テクスチャのシェイプメッシュで埋める（`fpsWallChamferFloorMeshes`） | 同上 |
| 隣接更新 | `TileNeighborBatch` が近傍タイルの再計算をバッチ化 | [tile-neighbor-batch.ts](../src/game/engine/rendering/tile-neighbor-batch.ts) |
| 未探索タイル | `unexplored` / `nothing` ならメッシュを削除。黒背景がそのまま見えるので境界はタイル単位の直線 | [tile-rendering.ts](../src/game/engine/rendering/tile-rendering.ts) `updateTile` |
| 後処理 | EffectComposer（TAA/FXAA + トーン調整） | [render-pipeline.ts](../src/game/engine/rendering/render-pipeline.ts) |
| 別経路 | XR 用インスタンシング（`XrTerrainBatches`、照明シェーダーフックを保持）、Quest ネイティブステレオへのリソース書き出し | `xr-terrain-batches.ts`, `quest-scene-export.ts` |

**設計上の結論**: 地形は非ライティングのまま、**共通シェーダーフックを「ワールドシェーディング」に拡張する**のが最も筋がよい。
Three.js の `PointLight` を多数置いて `MeshStandardMaterial` に切り替える案は、ドット絵の色が崩れる・
Quest/Android で重い・XR バッチとネイティブ書き出しの互換を壊す、の理由で採らない。

## 1. 壁形状: 斜めの隙間を見せる「角丸め」＋斜め連結

### 1.1 ゲーム規則の確認（NetHack `test_move`）

- **すり抜け**: P→Q の斜め移動で、直交する 2 マスがどちらも岩/壁なら「すり抜け」。
  所持重量 600 超・大型・倉庫番レベルでは通れない（荷物が少なければ通れる）。
- **扉**: 開いた扉・閉じた扉のマスとの斜め移動は不可。**扉のない出入口・壊れた扉は斜め移動可**。

### 1.2 形状ルール

壁タイルを「四隅それぞれが角張る／丸まる」正方形として扱う。既存の面取りマスクの考え方そのままで、
45° 面取りを **1/4 円弧（半径 = タイル半幅）** に置き換え、全カメラモードで有効にする。

```
角 c を丸める ⇔ c 側の直交 2 隣が両方とも「斜め通行可能マス」
  斜め通行可能 = 床・通路・扉なし出入口・壊れた扉
  不可        = 壁・岩・未探索・開/閉扉・（倉庫番レベルではすべて不可）
```

この 1 ルールで要望がすべて導ける。

| 配置 | 結果 |
| --- | --- |
| 孤立した壁 | 四隅すべて丸まる → **円柱** |
| 上下左右に連続 | 連続側の角は直交隣が壁なので角張る → **ひとつなぎの壁**。端だけ半円キャップ |
| 斜めに並び、間の 2 マスが両方床 | 向かい合う角が丸まり、柱の間に **≈0.41 タイルの隙間** が見える → すり抜けられることが伝わる |
| 斜めに並び、間の片方が岩/未探索 | その角は角張る → 角同士が接して **斜めにひとつなぎ** |
| 扉の隣の壁 | 扉側の角は角張る → **四角いまま** |
| 倉庫番 | すり抜け不可なので丸めない（隙間を見せない） |

**斜め連結の仕上げ（任意）**: 「間の片方 B が岩」の場合、角が点で接するだけだと階段状に見える。
B マスの W1/W2 側の半分（三角形）を壁で埋めると、通行側 A に 45° の面を向けたなめらかな斜め壁になる。
B はメッシュを持たないことが多いので、面取り床メッシュと同じく別マップ（`wallDiagonalFillMeshes`）で管理し、
W1/W2/A/B の更新時に `TileNeighborBatch` で再計算する。

### 1.3 実装方式

1. **形状の生成**: 4bit 角マスク（＋斜め埋め用の追加ビット）→ 2D 輪郭 → `ExtrudeGeometry`（高さ `WALL_HEIGHT`）。
   マスクごとにキャッシュ（最大 16 通り＋α）。円弧は 6〜8 分割で十分。上面の縁に小さなベベルを付けると陰影が締まる。
2. **UV**: 曲面の側面は輪郭の弧長を u にする。隣接タイルとの継ぎ目が出ないよう、
   直線部は今と同じ UV、円弧部だけ弧長で伸ばす。高解像度壁タイルとの整合は 1 タイル＝テクスチャ 1 枚を維持。
3. **空いた床**: 既存 `upsertFpsWallChamferFloorMesh` を円弧形状に一般化して流用。
4. **判定関数**: `isPassableTileForFpsDiagonal` を「扉の種類」を見るよう改修（現状は出入口を一律通行可扱い）。
   扉グリフ（開/閉）と扉なし出入口（`S_ndoor`、壊れた扉も同じ表示）を区別する。
5. **影響範囲の確認対象**: `floor-occlusion.ts`（角に沿った AO）、`wall-overlays.ts`（側面オーバーレイ）、
   `xr-terrain-batches.ts`（マスク別にインスタンスグループを分ける）、`quest-scene-export.ts`、ピッキング。
   Vulture 表示は対象外（従来どおり）。
6. **オプション**: `wallShapeStyle: "block" | "chamfer" | "round"`。既定は round、従来見た目にも戻せる。

## 2. ライティング: ライトフィールド＋動的光源

### 2.1 シェーダーの式（共通フックを置き換え）

```
color = albedo
      × faceShade                       // 既存の面陰影（キーライト分は弱める）
      × ( ambient                        // 暗所でも真っ黒にしない下限
        + lightField(xy + n·0.5)         // 2.2: 部屋・静的光源の焼き込み（壁は面の手前をサンプル）
        + Σ dynamicLight_i(N·L, 減衰, ゆらぎ) )  // 2.3: 最大 8 灯
      × memoryTint                        // 4.1: 視界外の記憶部分を暗く・彩度を落とす
      × exploredMask                      // 3: 未探索境界のフェード
```

- 壁はスクリーン微分で得た法線方向に 0.5 タイルずらしてライトフィールドを引くことで、
  **部屋側の面だけが照らされ、裏側（通路側）は暗い**という正しい見え方になる。
- 「ライティング無効」設定では今のビネット経路をそのまま使う（互換・低スペック用）。

### 2.2 ライトフィールド（CPU で作るグリッドテクスチャ）

- マップ 80×21 を 1 マス 4×4 サブセルで `DataTexture`（RGB、リニア補間）に焼く。更新はターン単位・差分だけ。
- 遮蔽: 既知マップ上の簡易シャドウキャスティング（壁・岩・閉扉が遮る）で光が壁を貫通しないようにする。
- **明るい部屋**: 明るい床グリフ（`S_room`、`S_litcorr`）の連結領域を部屋として検出し、
  内側の四隅（不定形な部屋は凸角）に壁高 0.8 程度の仮想光源を置く。
  部屋全体が 85% 以上の明るさになるよう減衰を調整し、四隅と壁面がやや明るい「部屋全体が照らされている」絵にする。
  装飾として四隅に燭台スプライトを置く案もある（オプション）。
- 暗い部屋・通路: ambient のみ（＋プレイヤー光源）。

### 2.3 動的光源（uniform 配列、最大 8 灯）

| 光源 | 判定材料 | 色・ふるまい |
| --- | --- | --- |
| 獣脂/蜜蝋ろうそく、燭台、油ランプ | 持ち物の「(lit)」 | オレンジ（≈2200K）。強いゆらぎ（8–12Hz の小振幅＋ゆっくりした揺れ、位置も微小に揺らす） |
| 真鍮のランタン | 同上 | 暖白（≈3000K）。ゆらぎ弱め |
| 魔法のランプ | 同上 | 青白（≈7000K）。ゆらぎなし、ゆっくり脈動 |
| 光の呪文・光の巻物 | メッセージ（「A lit field surrounds you!」等）＋その後明るくなったマス | ライトフィールド側に青みを付けて焼き込む |
| 光るモンスター（yellow light、fire elemental 等） | モンスターグリフ→「発光」テーブル | 種族ごとの色 |
| 溶岩・火の罠・爆発/光線エフェクト | 地形/エフェクトグリフ | 溶岩は赤橙のゆらぎ光、エフェクトは短時間の閃光 |

- 光源半径はゲームの値（ランプは 1、燭台は最大 4 など）を基準に、見た目は +1.5 タイル程度の柔らかい減衰にする。
- 灯数が 8 を超える場合はプレイヤーに近い順。あふれた分はライトフィールドに焼き込む。

### 2.4 データの精度とネイティブパッチ

ウィンドウポートの情報だけでは「部屋が明るいか」「今見えているか」は推定になる（明るい床グリフ＝視界内で明るい、など）。
正確にするには [runtime-native-patches](runtime-native-patches/README.md) の仕組みで次を書き出すのが確実:

- `levl[x][y].lit`（部屋の明暗）、`viz_array` の `cansee` ビット（今見えているか）
- `light_base` の光源リスト（位置・半径・種類: 物体/モンスター）

**まずはグリフ・持ち物・メッセージからの推定で実装し、ネイティブ書き出しは第 2 段階**とする
（3.6.7 / 5.0 / Slash'EM の 3 ランタイムを再ビルドする必要があるため）。

## 3. 未探索と探索済みの境界をなめらかにする

### 方式: 探索マスク＋ノイズ閾値＋フェードイン

1. **探索マスク**: 1 マス 4×4 サブセルの `DataTexture`。探索済み 1 / 未探索 0。
   ガウスぼかし（半径 ≈0.6 マス）を CPU で差分更新する。
2. **シェーダー**: `exploredMask = smoothstep(0.35, 0.65, mask + noise(xy)·0.15)`。
   ノイズで格子感を消し、境界を不定形のにじみにする。
3. **はみ出し**: 境界の外側 1 マスに「にじみ板」（暗い床色の平面、マスクでアルファ）を描き、
   探索済み領域が黒へ溶けていくようにする。メッシュは未探索セルには作らない（ピッキング・既存ロジックに影響させない）。
4. **時間方向**: 新しく見えたマスはマスク値を 0→1 へ 250ms 程度で補間（「霧が晴れる」演出）。
5. **壁**: 壁は境界に立つことが多いので、壁の外側面（未探索側）はマスクで沈め、上面の縁だけ残す。

ライトフィールドと同じテクスチャ解像度・座標系にすれば、1 枚の RGBA（RGB=光、A=探索）にまとめられる。

## 5. 実装順序

| 段階 | 内容 | 理由 |
| --- | --- | --- |
| P0 | 共通シェーダーフックを `world-shading` に分離、品質プリセットとデバッグ切替 | 以降すべての土台。既存ビネットは Low として温存 |
| P1 | 探索マスク（3 章） | 独立していて小さく、効果が見えやすい |
| P2 | 壁の角丸め・斜め連結（1 章） | 既存面取り基盤の一般化。高解像度壁タイルの UV 確認と同時に進められる |
| P3 | ライトフィールド＋部屋の四隅光源＋プレイヤー光源とゆらぎ（2.2, 2.3） | 見た目の変化が最大。P0 の式に乗せる |
| P4 | 光るモンスター・溶岩・魔法光・記憶色調（2.3 残り, 4.1） | 推定ロジックの追加 |
| P5 | ネイティブ書き出し（2.4）で推定を正確なデータに置換 | 3 ランタイム再ビルドが必要 |
| 随時 | 4.2〜4.7 | 独立した小粒の改善 |

### 実装済み（P0・P1）

- `rendering/world-shading.ts` — 共通シェーダーフックと uniform を `Lighting` から分離。既存の呼び出し
  （`patchMaterialForVignette`, `vignetteUniforms`）はそのまま使える。モンスター・アイテム・プレイヤーなど
  未知のマスの上にも描かれるものは `entity: true` を渡し、地形専用の効果を受けない（スプライトは自動で除外）。
- `rendering/explored-mask.ts` — 地形メッシュがあるマスを毎フレーム集計し（3.6.7 の空白の石は除外）、
  1 マス 8×8 テクセルの 1 チャンネルテクスチャにガウスぼかしを解析的に焼く（全マップ再計算で 1ms 未満）。
  境界でちょうど 0.5、内側 0.4 マス程度で 1 になる。新しく見えたマスは 260ms でフェードイン、
  レベル移動では即座にリセット。ターミナル表示と Vulture タイルでは無効。
- 設定「探索範囲の境界をぼかす」（`smoothExploredEdges`、既定オン）を追加。
- 調整用に開発者コンソールから `__nh3dExploredMask.get() / set({...}) / reset()` を使える。
- **品質プリセットは P3 へ延期**: 現時点でまとめる機能が 1 つしかないため、個別の設定にとどめた。
- 「はみ出し」の板（3 章の 3）は入れていない。境界の内側でフェードさせるだけで十分なめらかだったため。

### 新設モジュール案（P3 以降）

- `rendering/light-field.ts` — ライトフィールドの CPU 生成と `DataTexture` 管理（探索マスクと同じ座標系で、RGB=光・A=探索の 1 枚に統合できる）
- `world/light-sources.ts` — 持ち物・モンスター・地形・メッセージからの光源推定
- `rendering/wall-shape.ts` — 角マスク→輪郭→押し出しジオメトリのキャッシュ（`WallGeometry` から利用）

### 注意点

- **Quest ネイティブステレオ**は解決済み Three リソースを書き出す方式のため、シェーダー差し込みは自動では伝わらない。
  当面は Quest ネイティブ経路を Low 相当に固定し、パリティは別課題とする。WebXR（Wolvic）経路はインスタンス材質が照明フックを保持するので、uniform 追加で追従できる。
- 新しいテクスチャ・ジオメトリ・メッシュはレベル変更とエンジン破棄の解放処理に必ず登録する（[engine README](../src/game/engine/README.md) の Engine disposal）。
- 壁形状の変更はピッキング（クリック判定）・FPS の衝突感・AO の位置ずれを起こしやすい。マスク別スナップショットテストを用意する。
